# 联机架构：Minecraft 式客户端 / 服务端

> zombie-raid 的联机采用与 Minecraft 相同的**严格 C/S 分层**：
> 服务端（主机）是唯一权威，客户端是「渲染器 + 输入器」。
> 单人游戏就是一台不开端口的本地权威服务端（MC 的 Integrated Server 模式）。

## 1. 概念对照表

| Minecraft 概念 | zombie-raid 实现 | 位置 |
|---|---|---|
| 集成服务端 Integrated Server | 主机玩家进程内跑权威模拟（开房即「对局域网开放」） | `net.gd host_game()` |
| 专用服务端 Dedicated Server | 路线图：`--server` 无头模式 | 见 §6 |
| 20 TPS 固定 tick | 主机 20 TPS 心跳累加器（防 stall 上限 10 tick） | `net.gd _server_tick()` |
| 服务端权威世界模拟 | 丧尸 AI / 刷怪 / 计时 / 掉落只在主机跑 | `raid_manager.gd`（客户端门控） |
| 服务端校验（反作弊） | 命中上报：限频 20/s、伤害 ≤80、射程 ≤80m | `net.gd rpc_hit_zombie` |
| 客户端预测（本地玩家） | 本地玩家完全自模拟，15Hz 位置上行（MC 同款：移动客户端权威） | `world_raid.gd _process` |
| 远程实体插值 lerpSteps=3 | 丧尸快照缓冲，渲染在 3 个快照之前（15Hz≈200ms） | `zombie.gd _net_physics` |
| 实体生命周期包 | 快照里首次出现 → 客户端惰性镜像 `Z_<id>`；死亡走可靠 RPC | `net_spawn_mirror` / `rpc_zombie_dead` |
| 未知实体静默忽略 | 找不到的 `Z_<id>` 不崩溃，镜像兜底 | `rpc_zombie_states` |
| delta 编码 | 未做：全量快照 14 丧尸 × 7 float @15Hz ≈ 6 KB/s，不值得 | 取舍见 §5 |
| 区块流送 | 世界种子一次同步 + 各端确定性重建程序化城市 | `world_raid._sync_net_seed` |
| Open to LAN | 随时 F5 开房，世界不必重开（回溯分配实体 id） | `net_lobby.gd` |

## 2. 数据流

```
        主机 (authority, 20 TPS tick)                    客户端 (thin client)
  ┌────────────────────────────────┐            ┌──────────────────────────────┐
  │ 丧尸 AI / 刷怪 / 撤离计时 / 掉落 │            │ 本地玩家自模拟（预测层）        │
  │         │ _server_tick()       │            │   │ 15Hz 位置/朝向 上行        │
  │         ▼                      │   ENet     │   ▼                          │
  │  丧尸快照 [seq,id,x,y,z,yaw,   │ ────────▶  │ 插值缓冲(8) ──▶ 渲染(延迟3快照)│
  │            anim,type] 15Hz    │            │   首见 → 惰性镜像 Z_<id>       │
  │  时钟/狂暴阶段 1Hz             │ ────────▶  │ manager.net_sync_clock()     │
  │  命中校验(限频/伤害/距离)       │ ◀──────── │ 上报命中 net_id+伤害           │
  │  拾取认领(按坐标, 先到先得)      │ ◀──────── │ 拾取 → claim_box(pos)         │
  │  团灭广播 / 撤离成功广播         │ ────────▶ │ 全队同生共死                   │
  └────────────────────────────────┘            └──────────────────────────────┘
```

## 3. 世界一致性（种子协议）

程序化城市 + 地牢 + 战利品分布全部由全局 RNG 驱动，因此：

1. 主机建世界时固定 `seed(raid_seed)`，并 `rpc_seed(seed, elapsed)` 广播；
2. 客户端收到后 `pending_seed` 暂存 → `reload_current_scene` → 用同一种子重建；
3. 未拿到种子的客户端**不建世界**（等待覆盖层），主机断线则自动转单机；
4. 每轮新 raid（撤离/团灭重开）主机重新播种再广播，迟到者比对种子自动重载。

## 4. 实体同步细节（快照格式）

```
PackedFloat32Array:
[0]        seq          单调递增快照序号（丢包容错：跳号照常插值）
[1+i*7]    net_id       实体 id（主机递增分配，节点名 Z_<id>）
[+1..3]    x,y,z        权威位置
[+4]       yaw          模型朝向
[+5]       anim code    1=待机 2=跑 4=攻击
[+6]       type         0..2=变体(Runner/Walker/Brute) 3=喷吐者
```

客户端侧 `zombie.gd`：8 深度环形缓冲，播放头 = 最新 seq − 3，
在跨越播放头的两个样本间插值；跳变 >10m 直接吸附（传送/长停顿）。

## 5. 取舍与已知限制

- **玩家位置不做服务端重演**：MC 单机/联机的移动同样是客户端权威 + 服务端校验；
  本作把校验预算花在命中上（射击是这个游戏的可疑行为大头）。
- **玩家小队音效不对称**：主机能听到全部丧尸，客户端只能听到本地事件
  （`Sfx` 是位置音频，未随快照广播）——v1 接受。
- **武器/弹药拾取不互斥**：箱子（战利品/医疗包）先到先得，武器人人可拿。
- **喷吐者酸弹只在主机存在**：远程玩家暂不受酸弹伤害（近战爪击已覆盖远程玩家）。
- **快照全量不做 delta**：当前规模带宽≈6KB/s，delta 复杂度不值。
- **专用服务端**：`$PlayerInstance` 与世界耦合较深，留作路线图
  （思路：`--server` 启动参数 → 剥离 Avatar/相机，`Sfx` 静音，无头渲染）。

## 6. 怎么玩

1. 两台机器各启动游戏（同一局域网，或主机做 UPnP/端口转发 UDP 24565）；
2. 任意一人 F5 开房（世界继续跑，可以中途开房）；
3. 其他人左下角输入主机 IP，F6 加入 → 自动重建同一种子世界；
4. 主机已在中途 → 直接跳过商店进场； raid 时钟/狂暴 1Hz 对时；
5. **任一玩家死亡 = 全队 raid 失败**；任意一人站进撤离光柱 3 秒 = 全队结算。
